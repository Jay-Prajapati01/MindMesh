# Security Policy

## Supported versions

Security fixes are made against the latest code on the `main` branch. There are no separately maintained release branches at this time.

## Reporting a vulnerability

Please do not open a public issue for an undisclosed vulnerability. Use GitHub's **Report a vulnerability** option on the repository's Security tab to send a private report. Include the affected component, impact, steps to reproduce, and any suggested mitigation. Do not include real user data or live credentials in the report.

We will acknowledge reports as soon as practical, investigate them, and coordinate a fix and disclosure with the reporter.

## Credential exposure

If a credential is committed accidentally, revoke or rotate it with its provider immediately. Removing it from the latest commit does not invalidate copies in Git history, forks, caches, or logs.
